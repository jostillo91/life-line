# Life Line

Life Line is a private, local-first life archive. Its primary experience is a chronological canvas for writing and revisiting memories without demanding exact dates.

The public frontend deployment is `https://jostillo91.github.io/life-line/`, published from `main` through GitHub Actions. Only application assets are hosted: a new production archive starts empty, existing local data is preserved, and the AI server is not deployed or enabled. Localhost and the hosted origin have separate storage; use Backup & Restore to move an archive manually. Install on iPhone before restoring into that installation, and keep regular full/encrypted backups: Pages is not archive backup. See the GitHub Pages section in `ARCHITECTURE.md` for setup and phone/offline checks.

Life Line now has a production PWA manifest, existing-brand icons, optional installation and an application-only offline shell. After loading successfully online once, supported browsers can cold-start and use the local archive without the app server. Remote AI/address lookup need connectivity; Life Map keeps local coordinates and related records available without offline tile requests. Updates require approval and protect open capture/editor work and pending saves. Backup & Restore offers optional browser storage persistence and usage/quota status. Installing is not a backup: keep regular full backups. See the existing architecture documentation for caching, deployment, browser limits and the physical-phone checklist.

Quick Capture is the fast, body-first path into normal Memories, available from the shared header or Ctrl/Cmd + Shift + M. Title, event date and attachments are optional; unknown dates default to Unsorted Memories, not today. One local draft can be resumed after closure/refresh or explicitly discarded. Save offers Done or the existing full editor, without forcing organization. Capture uses local storage/media only, with no AI, authentication or API credits; once the app is loaded it does not require an internet connection. See the existing architecture documentation for storage limits and future voice-input compatibility.

The Timeline explores Entire Life, Decades, Years, Months, and Days with focal-preserving zoom, important Memories, metadata-only clusters, uncertainty/range tracks, Life Era bands, optional birthday-based ages, date/year/era jumps, and a density overview. Local filters, horizontal mouse/trackpad/touch navigation, accessible controls, keyboard interaction, and close-scale date confirmation/undo need no AI/API. Birth date is optional archive metadata included in backups; navigation state is session-only. See the existing architecture documentation for conventions, clustering limits, and isolated development fixtures.

Current features include timeline browsing, deliberate date movement with undo, uncertain dates, debounced editor autosave and recoverable drafts, local persistence, life-data management, story galleries, a Media Library, review-first bulk photo import with local EXIF suggestions and duplicate detection, private GPS-based Place suggestions, and versioned full backup/restore with original media and integrity validation. Backups can be standard ZIP files or optional locally encrypted files; neither is uploaded by Life Line. Backups remain local files that the user must store somewhere durable, and an encrypted backup cannot be recovered without its password.

Memory History is durable, local-only previous-state preservation, distinct from drafts and seven-second undo. Open History from an existing memory's detail or editor to compare read-only versions and explicitly restore one without removing newer history. Existing memories start accumulating history on their first meaningful edit after upgrading; migration invents no past. Autosaves coalesce into editor-session/five-minute checkpoints, while date moves, accepted assistant edits, relationship operations, and restores have distinct checkpoints. History is included in JSON v3 and full ZIP v3/encrypted backups (legacy v1/v2 remain readable), never ordinary Timeline, Search, or AI evidence. Deleted references are reported and omitted during restoration; deleted files/entities are never recreated. See the existing architecture/data-model documentation for retention and Merge policies.

Recovery Center is available under Backup & Restore, without adding primary navigation. Normal deletion keeps the canonical memory and all history; seven-second Undo remains available, and later recovery needs no network. Deleted memories have newest-first metadata and read-only previews. Restore preserves identity, creation date and content, omitting unavailable references with warnings. Separate permanent deletion and Empty Trash require typed confirmation and remove owned history atomically, never media files. There is no automatic expiration. Complete backups include deletion state; conservative Merge preserves conflicting local records as separate copies. Deleted memories are excluded from ordinary views, media linkage counts, Search, semantic indexing and Ask evidence; restored memories await explicit reindexing.

Life Map visualizes existing Places, associated Memories and media, and optional unassigned GPS media. Map tiles may contact an external provider when viewed; address lookup is separately opt-in and unavailable until a provider is configured. No stories or photos are uploaded by either feature.

Memory Assistant is optional. Its development-only local mock works without an AI service; production does not present mock suggestions as real AI. Live OpenAI suggestions require connectivity, explicit consent and a separately configured server-side API. AI suggestions never become archive facts until accepted by the user. See `docs/ARCHITECTURE.md` for privacy and deployment configuration.

Search offers local keyword results with year, Life Era, Person, Place, Tag, and type filters. Optional semantic search requires explicit opt-in and indexing; it keeps the numeric index locally while the configured embedding provider receives only selected Memory text and explicit queries. Results open the original Memories. The local development mock incurs no paid calls. See `docs/ARCHITECTURE.md` for privacy, incremental-index, and server configuration details.

Ask Life Line, within Search, retrieves a small set of original Memories before offering a grounded answer with clickable source citations. It uses the existing semantic index when enabled and falls back to keyword/structured retrieval otherwise. The source preview precedes remote answer synthesis; Ask sessions are disposable and never alter Memories. See `docs/ARCHITECTURE.md` for evidence, citation, and uncertainty limits.
