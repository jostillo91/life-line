# Roadmap

**Frontend hosting** — GitHub Pages deployment configuration publishes only the audited static PWA from `main`, supports manual dispatch and repository/custom-domain base paths, and disables remote AI in that build. Production starts with an empty device-local archive; backup restoration is manual and hosting is not cloud backup. See the architecture's Pages/iPhone verification checklist. No backend hosting, archive upload, analytics or cloud synchronization is included.

**Fast capture** — body-first Quick Capture is complete: optional title/rough date/local attachments, recoverable single draft, desktop shortcut and mobile-friendly entry, existing Unsorted integration, ordinary search/backup/history participation, and optional full-editor handoff. No AI/cloud dependency or separate notes model. The shared body-update path is ready for future voice input, but recording/transcription and multi-device sync remain future work.

**Installable/offline foundation** — production PWA shell/manifest, existing-brand icons, supported-browser installation, offline local archive/capture/media/backup, network-only remote features, tile-free offline location lists, consent-based safe updates and optional storage persistence are implemented. Canonical data remains outside service-worker caches. The previous physical-phone PWA checkpoint is accepted as verified per the user's instruction. New Recovery Center behavior has production-browser/server-unavailable and 390px responsive checks; Recovery-specific physical-phone/download round-trip checks remain user verification. Retain the documented real-device checklist for future releases. Push/background/cloud sync are not included.

1. **Foundation** — timeline, entries, uncertain dates, persistence, CRUD, autosave, and durable Memory Revision History are complete. History offers read-only comparison, coalesced editor checkpoints, confirmed restore retaining newer versions, and safe missing-reference handling. No event-sourcing rewrite is needed.
2. **Life organization** — people, places, tags, eras, basic relationship navigation, local GPS clustering/Place confirmation, Life Map, and filtered keyword/opt-in semantic search are complete. Explicit reverse geocoding is available when a provider key is configured. More advanced search exploration remains later work.
3. **Media** — local binary storage, thumbnails, library/gallery presentation, SHA-256 duplicate detection, review-first bulk photo import, confirmed Media-to-Place relationships, and map navigation are complete.
4. **Advanced timeline** — focal-preserving five-scale exploration, importance-aware canonical clustering, uncertainty/range tracks, Life Era bands, optional archive-owned birth date/age display, jumps, density overview, local filters, accessible responsive panning, and detailed date movement/undo are complete. A 2,000-Memory development fixture verifies bounded rendering. Fine-grained animated/pinch zoom and more sophisticated grouping remain optional future work.
5. **Archive and preservation** — versioned full ZIP backup, optional password-protected encrypted backup, validated Merge/Replace restore, original-media integrity checks, JSON data export, and durable revision preservation in all three exports are complete. Recovery Center adds offline soft deletion, read-only previews, same-identity restoration, retained immediate Undo, separated typed permanent deletion/Empty Trash, atomic owned-history cleanup and media preservation. Schema 8/ZIP and JSON v3 preserve history/deletion state without synthetic migration states; v1/v2 backups remain readable. Deleted memories stay out of ordinary views and AI/search evidence. Scheduled/cloud backup, optional retention policy, broader archive maintenance and book/PDF output remain. Neither trash nor history expires automatically.
6. **AI assistance** — the optional Memory Assistant, deterministic mock, constrained context, explicit acceptance, and a separate, session-protected OpenAI Responses API endpoint are complete. Ask Life Line adds bounded retrieval-first, source-cited synthesis through that endpoint, with disposable follow-ups and keyword fallback. A production deployment must supply server-only secrets, HTTPS, and an exact allowed origin before enabling paid remote requests. Accepted assistant edits now create ordinary revision checkpoints; pending/rejected proposals remain disposable and history is excluded from default AI evidence. Broader evidence quality evaluation and richer suggestion provenance remain later work. AI never silently rewrites canonical memories.
